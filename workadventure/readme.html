Overview

This collection is maintained by Openline in its official brand-assets repository. It provides interface references for a WorkAdventure-based virtual office; WorkAdventure remains a separate upstream project with its own ownership and terms.

The version counts and feature descriptions below document earlier snapshots and prototype behavior. Inspect each page's external dependencies, data handling, and actual integration before production use; a preview does not establish a working backend, shared persistence, or an endorsed partnership.

🚀 Quick start: Open index.html to browse all apps. Click any app to launch it. Embed via WorkAdventure's iFrame configuration.

🔗 Embedding in WorkAdventure

All apps are designed to be embedded as iFrames in WorkAdventure zones. Configure the iFrame URL in your WorkAdventure map editor.

<!-- WorkAdventure map.json iFrame configuration -->
{
  "type": "object",
  "name": "Dashboard",
  "properties": {
    "openWebsite": "https://your-host/openline-apps/dashboard.html",
    "openWebsiteAllowApi": true,
    "openWebsitePolicy": "allow-popups",
    "openWebsiteWidth": 900,
    "openWebsiteHeight": 600
  }
}
map.json

Close Button Pattern

Every app uses the WorkAdventure postMessage API to close the iFrame:

// Sends close signal to WorkAdventure parent
window.parent.postMessage({ type: 'dashboard-close' }, '*');
// Fallback for standalone testing
|| history.back()

💡 Each app uses {type: '<appname>-close'} — e.g. chat-close, pomodoro-close, soundcloud-close.

⚙ WorkAdventure SDK

Apps can interact with WorkAdventure beyond just close events. The full WA Scripting API is available when openWebsiteAllowApi: true:

// Listen for WA room events
WA.room.onEnterLayer('meeting-zone').subscribe(() => {
  // Auto-open standup when player enters meeting zone
});

// Send player data to app
WA.player.onPlayerMove.subscribe(({ x, y }) => {
  document.dispatchEvent(new CustomEvent('player-moved', { detail: {x,y} }));
});
